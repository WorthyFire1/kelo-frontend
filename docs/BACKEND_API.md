# API backend КЕЛО

Frontend подключён к фактическому контракту WoodMarket. Базовый адрес задаётся через `VITE_API_BASE_URL` и должен заканчиваться на `/api`.

## Публичные данные

- `GET /Home` — данные главной страницы и новинки;
- `GET /Catalog/categories` — категории;
- `GET /Catalog/products` — товары, фильтры и пагинация;
- `GET /Product/{slug}` — товар, варианты, отзывы и похожие товары;
- `GET /Blog`, `GET /Blog/{slug}` — публикации;
- `GET /Brand`, `GET /Brand/{slug}` — бренды;
- `GET /Discount` — активные акции;
- `GET /CustomOrder/info` — условия индивидуального изготовления.

## Авторизованный покупатель

- `/auth/register`, `/auth/login` — регистрация и вход;
- `/user/profile`, `/user/stats`, `/user/change-password` — личный кабинет;
- `/Cart/GetCart`, `/Cart/add`, `/Cart/update`, `/Cart/{id}`, `/Cart/clear` — корзина;
- `/Wishlist`, `/Wishlist/{productId}` — избранное;
- `/Order`, `/Order/{id}`, `/Order/{id}/cancel` — заказы;
- `/Order/statuses`, `/Order/payment-methods`, `/Order/shipping-methods` — справочники оформления;
- `/CustomOrder`, `/CustomOrder/{id}` — индивидуальные заявки;
- `POST /Product/{productId}/reviews` — отзыв на модерацию.

JWT передаётся в заголовке `Authorization: Bearer <token>`. Refresh token текущим backend не поддерживается: при ответе `401` frontend завершает локальную сессию.

## Администрирование

Frontend использует реализованные маршруты `/admin` для статистики, товаров, категорий, заказов, пользователей, брендов и публикаций блога. Активные скидки доступны только для чтения через `/Discount`.

## Ограничения текущего backend

- создание заказа не принимает промокод и не применяет скидку;
- нет административных маршрутов для скидок и индивидуальных заявок;
- нет административного маршрута модерации отзывов;
- нет API для обратной связи и подписки на рассылку;
- варианты товара не участвуют в серверном расчёте цены и остатков;
- модель бренда не содержит признака активности, хотя он присутствует в DTO;
- проверка роли на `AdminController` отключена в backend, поэтому frontend-проверка роли не является защитой API;
- `/auth/refresh` возвращает ошибку «Refresh token не поддерживается»;
- публичный DTO товара не отдаёт настоящий SKU;
- создание индивидуальной заявки без авторизации конфликтует с обязательным `UserId` в модели, поэтому frontend запрашивает вход.
